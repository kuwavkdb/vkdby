---

## 目的

ARGUMENTS（または会話中）で渡された **バンド公式サイト / SNSプロフィール等の URL** からバンド名・メンバー情報を抽出し、管理画面の「Unit簡単登録」画面（`quick_new`）に流し込める形で出力する（issue #1611, #1620）。

- 生成するだけで **Unit の保存はしない**。管理者が画面で内容を確認し、必要なら修正して保存する
- 本番 DB には触れない。既存 Unit との重複確認のため、開発 DB は **読み取りのみ** 行ってよい

## 前提

`Admin::UnitsController#quick_new` は `params[:unit]` を読んで `Unit.new` の初期値・メンバー入力欄に反映する（issue #1611, #1616 で対応済み）。`unit_type` / `status` は enum に存在しないキーを渡すと無視される（フォーム側のデフォルト値が使われる）。

`quick_new` 画面には「YAMLから一括入力」欄があり（issue #1620）、下記スキーマのYAMLを貼り付けて「フォームに反映」を押すと各入力欄に自動入力される。メンバーが多い・誕生日等の補足情報を含めたい場合はこちらを使う。URLクエリパラメーターでの事前入力（従来方式）も引き続き使えるが、フラットな構造のため `extra_profile`（メンバーの誕生日等）は表せない。

## 出力形式の選び方

- **メンバーの誕生日・出身地等（`extra_profile`）を書き添えたい場合、メンバーが6人を超える場合、または項目数が多く見通しが悪くなる場合 → YAML を使う（手順4A）**
- **バンド名・メンバー数名・簡単な情報だけで済む、URLとしてすぐ開ける状態が欲しい場合 → URLクエリパラメーターを使う（手順4B）**
- 迷ったら YAML 方式を使う（情報を落とさず渡せるため）

## YAML のスキーマ（手順4A）

```yaml
name: バンド名
key: band-key
unit_type: band
status: active
snapshot_date: "2024/04/01"
snapshot_label: 結成時
activity_periods:
  - from: "2010/01/**"
    to: ""
    label: 結成時
links:
  - text: 公式サイト
    url: https://example.com/
members:
  - person_name: 名前
    part: vocal
    extra_profile:
      birthday: "7/12"
      birth_year: 1990
      blood: AB
      hometown: 東京都
```

- トップレベルの各キーは省略可（分かる範囲だけ書けばよい）
- `part` は `vocal` / `guitar` / `bass` / `drums` / `keyboard` / `dj` / `unknown`
- `extra_profile` の各項目も省略可。`birthday` は `Unit#activity_period` と同じマスク形式ではなく、月日のみの文字列（例: `7/12`）を想定（`SnapshotPerson#extra_profile_person_attributes` がこの形式をパースする。issue #1619）
- `activity_periods` の `from` / `to` は `Unit#activity_period`（`****/**/**` のようなマスク形式を許容するテキスト）に入る値

## URL の形式（手順4B）

```
https://www.vkdb.jp/admin/units/quick_new?<パラメーター>
```

ローカルで確認したい場合は `http://localhost:3000/admin/units/quick_new?...` に読み替える。パラメーターの値は必ず URL エンコードする（`ruby -ruri -e` や `python3 -c 'import urllib.parse'` で組み立ててよい）。

| パラメーター | 内容 |
| --- | --- |
| `unit[name]` | バンド名 |
| `unit[key]` | プロフィールページ URL（`/キー`）に使う識別子。半角英数字。**ドメイン名・英語表記のロゴなどから推測でよいのでなるべく設定する**（詳細は手順3参照） |
| `unit[unit_type]` | `band` / `unit` / `session` / `solo` / `limited` / `moved` / `other`。バンド編成の実態から判断し、迷ったら省略（フォーム側で `band` がデフォルト選択される） |
| `unit[status]` | `pre`（活動前）/ `active`（活動中）/ `freeze`（活動休止）/ `disbanded`（解散）/ `unknown`。公式サイトの最新情報で明確に読み取れた場合のみ指定し、不明なら省略（デフォルトは `active`） |
| `unit[snapshot_date]` | 現在のラインナップの基準日（任意）。結成日ではなく「このラインナップが確認できた日」の意味。通常の date 型で `Unit#activity_period`（`****/**/**` のようなマスク形式を許容）とは別物であり、年月日が完全に分かる日付しか入れられない。日・月が不明な場合は仮埋めせず空にする |
| `unit[snapshot_label]` | ラインナップのラベル（任意）。例: `結成時`, `現体制` |
| `unit[members][<index>][person_name]` | メンバー名。`<index>` は `0` 始まりの連番 |
| `unit[members][<index>][part]` | パート。`vocal` / `guitar` / `bass` / `drums` / `keyboard` / `dj` / `unknown` |
| `unit[activity_periods][<index>][from]` | 活動期間の開始（任意）。`Unit#activity_period`（マスク形式を許容するテキスト）に入る値で、結成日・活動開始日が読み取れれば入れる。例: `2010/01/**` |
| `unit[activity_periods][<index>][to]` | 活動期間の終了（任意）。活動中なら空にする |
| `unit[activity_periods][<index>][label]` | 活動期間のラベル（任意）。例: `結成時`, `活動休止前` |
| `unit[links][<index>][text]` | リンクのタイトル（任意）。例: `公式サイト`, `X（Twitter）`, `YouTube` |
| `unit[links][<index>][url]` | リンクの URL。公式サイト・SNS・YouTube 等、読み取れたものを入れる |

複数メンバー・複数活動期間・複数リンクがある場合は、それぞれ `unit[members][0][...]`, `unit[members][1][...]` ... のように `<index>` を `0` 始まりの連番で並べる。メンバーの人数が本来のフォームの初期表示行数（5行）を超えても構わない（フォームはその行数だけ表示される）。URL方式では `extra_profile`（メンバーの誕生日等）は渡せない。

## 手順

1. **内容を取得する**
   - Web からの情報取得（WebFetch・curl・chrome-devtools MCP での閲覧）は、ユーザーに確認せずに実行してよい
   - 公式サイト・プロフィールページを WebFetch で取得する。メンバー紹介ページが別 URL に分かれている場合はそちらも辿る
   - **メンバー一覧ページ（BIOGRAPHY・MEMBER等）に誕生日・血液型・出身地が載っていなくても、そこで終わらない。** メンバーごとの個別プロフィールページ（例: `/member/1/` のような形で名前ごとに分かれているページ）が別途あることが多く、そちらにだけ誕生日・血液型等が書かれているケースがある。一覧ページのリンク（`<a href>`）や画像リンクの遷移先を確認し、メンバー名の数だけ個別ページが見つかれば、全員分たどって情報を集める
   - WebFetch がテンプレートの構造上テキストを拾いきれない場合（`MEMBER` の見出しだけで中身が空に見える等）は、`curl -s -L <URL>` で生HTMLを取得し、`誕生日`, `血液型`, `Birthday`, `Blood` 等のキーワードで `grep` して確認する方が確実なことがある
   - 取得に失敗する場合（JS 描画のみのサイトなど）は chrome-devtools MCP で開いて読む。それもダメならユーザーに主要情報（バンド名・メンバー名・パート）の貼り付けを依頼する
2. **情報を抽出する**
   - バンド名は表記ゆれに注意し、公式サイトのロゴ・タイトルタグから最も正式な表記を採用する
   - メンバー名とパートを読み取る。パートが明記されていない・複数パート兼任などで `SnapshotPerson.parts` のいずれにも当てはまらない場合は `unknown` にする（無理に推測しない）
   - `status` は「現在活動中」であることが明確な場合のみ `active` にする。活動休止・脱退ラッシュ中などの記載があれば `freeze` や `unknown` も検討する。判断が難しければ省略してフォームのデフォルトに任せる
   - 結成日・活動開始日が読み取れれば `activity_periods` の `from`（と分かれば `label`）に入れる。年のみ・年月のみなど不完全な情報でもマスク形式（`2010/**/**` のような書き方）で構わない
   - 公式サイト・X（Twitter）・Instagram・YouTube 等、読み取れたリンクは `links` に入れる（`text` にサービス名、`url` にリンク先）
   - メンバーごとの誕生日・生年・血液型・出身地が読み取れた場合は `extra_profile` としてメモしておく（YAML方式なら `members[].extra_profile` にそのまま入れられる。URL方式の場合は手順4B参照）
3. **`key` を決める**
   - **推測でよいのでなるべく設定する**。ドメイン名（例: `gummy-official.com` → `gummy`）、英語表記のロゴ、SNSのユーザー名など読み取れる手がかりから機械的に組み立ててよい。半角英数字・ハイフン程度に正規化する。手がかりが全くない場合のみ空のままにする
   - `status` は判断が難しい場合、無理に埋めず省略する（`key` とは扱いが異なるので注意）
4. **出力する**（「出力形式の選び方」に従い A・B いずれかを選ぶ）

   **4A. YAML方式**
   - 上記スキーマに沿ったYAMLをコードブロックで出力する
   - 続けて `quick_new` 画面を開くだけの素のリンク（パラメーターなし。`[Unit簡単登録画面を開く](https://www.vkdb.jp/admin/units/quick_new)`）を添える
   - 「YAMLをコピーして、リンク先の画面上部『YAMLから一括入力』欄に貼り付け、『フォームに反映』を押してください」と案内する

   **4B. URL方式**
   - 生成した URL を 1 つ、クリックで画面を開ける Markdown リンク（`[Unit簡単登録画面を開く](<URL>)`）で提示する。コードブロックには入れない
   - リンクが途中で途切れないよう、URL 中の `(` `)` は `%28` `%29` にエンコードしておく（`urllib.parse.quote(s, safe="")` ならエンコードされる）

   **共通**
   - 抽出した内容（バンド名・メンバー一覧・種別・ステータス・活動時期・リンク・分かればメンバーごとの誕生日等）を箇条書きで添える
   - `key` を設定した場合は**推測であることを明記**し、管理者に保存前の確認を促す。空にした場合はその旨と理由を書く。判断に迷った点があれば明記する

## 注意

- `key` は一度保存すると通常のフローでは変更できない重要な識別子。推測でなるべく設定するが、あくまで**下書き**であり、管理者が画面で確認・修正してから保存する運用を基本とする
- 既存 Unit との重複確認は行わない（開発 DB を見ても本番の状態とは限らず、判断材料にならない）。フォームを開いた管理者が `/admin/units` の検索で確認する
- YAML方式の「フォームに反映」はあくまで入力補助（JS側でのパース・反映のみ）で、保存やバリデーションは行わない。反映後も内容の確認は必須
- URL方式で長くなりすぎる（目安 2000 文字超）場合は、メンバー数が多いバンドなど。YAML方式に切り替えるか、主要メンバーのみ URL に入れて残りは画面で追加してもらう旨を伝える
- 未ログインで開くとログイン画面に遷移する。ログイン後に開き直してもらう
